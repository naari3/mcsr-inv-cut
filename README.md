# mcsr-inv-cut

MCSR の録画から、コンテナGUI (インベントリ、チェスト、作業台、かまど等) を開いている区間を自動検出し、時間の計測とカット動画の書き出しを行うツール。

- コンテナGUI の時間 / それ以外の時間 (その他GUI とゲーム画面の内訳つき) を計測
- コンテナGUI 区間を除去した動画、またはコンテナGUI 区間だけの動画を書き出し (フレーム単位、再エンコード)
- プレビューとタイムラインで自動判定を確認し、区間単位で手動修正

ffmpeg / ffprobe が PATH に必要。

## GUI

```
cargo run --release -- <video>
```

1. 動画を開く (ドロップでも可)。Webcam やチャットがゲーム画面に大きく重なる配信レイアウトでは「解析範囲を描く」でゲーム画面だけを囲う
2. 「解析する」。15 分の 1080p60 で約 2〜3 分
3. タイムラインで確認・修正する
   - Shift+ドラッグ / ダブルクリックで範囲選択し、`1` コンテナGUI、`2` その他GUI、`3` ゲーム画面、`0` 自動判定に戻す
   - `←` `→` で 1 フレーム移動、Shift 併用で区間の境界へ
   - `I` `O` で計測範囲の開始・終了
4. 書き出し

解析結果と修正は `<video>.mcsrcut.json` に自動保存され、次回開いたときに読み込まれる。

## CLI

```
mcsr-inv-cut analyze <video> [--roi x0,y0,x1,y1]
mcsr-inv-cut report <video>
mcsr-inv-cut csv <video> <out.csv>
mcsr-inv-cut cut <video> <out.mp4> [--mode remove-container|remove-gui|only-container] [--crf N] [--preset P]
```

## 判定方式

各フレームを幅 960 に縮小し、解析範囲内で次を計算する (`src/detect.rs`)。

- コンテナGUI: #C6C6C6 (±14) の連結成分のうち、次をすべて満たすものをパネルとみなし、面積比を `panel` とする。`panel >= 0.02` でコンテナGUI
  - 解析範囲の 5% 以上の大きさで、解析範囲の端に接していない
  - 水平・垂直それぞれ 1 辺以上が直線 (辺の内側 1〜2px の被覆率 0.85 以上)。ツールチップが 2 辺を隠すことがあるため 4 辺は要求しない
  - パネルの外側の帯の明るい画素が 15% 以下 (GUI を開くと背景が暗転するため)
- その他GUI: パネルがなく、ハートの赤 (R>=190, G<=70, B<=70) の画素比 `red` がしきい値未満。GUI 画面では HUD ごと暗転してハートの赤が消えることを利用している

## 検証ログ

2026-11-02

観察:
- gapcheck.mp4 (1080p60、Webcam なし、15:00) で、ホットバーの暗転とパネルの有無による参照ラベルと比べた。参照のコンテナフレームのうち、`panel` が取れなかったのは 35 フレームで、すべて区間境界の ±3 フレーム以内だった (参照は 10fps サンプリングのため境界がずれる)
- 誤検出の初期例は、雪・石英などカメラに近い平面が #C6C6C6 付近になったもの。解析範囲の端の除外と外側帯の暗さ条件で消えた。外側帯のしきい値を 0.25 から 0.15 に下げても、本物のコンテナ判定は 1 フレームも減らなかった
- ツールチップがパネルの下辺・右辺を覆い、連結成分が分断されるフレームがある。直交する 2 辺の条件にして拾えるようになった
- runs.mp4 (配信レイアウト、Webcam・チャット付き、解析範囲は全体のまま) では 105 区間を検出した。境界フレームを目視し、開始直前がゲーム画面、開始フレームがチェスト、終了直後がゲーム画面であることを確認した
- 書き出し: gapcheck のコンテナ除去版が 765.400 秒 (計測値の「コンテナGUI以外」と一致)。当初、出力側の `-r` がなく 25fps で間引かれていた問題を修正した
- gapcheck は PTS 列に 1 か所 2 フレーム分の隙間があり、可変フレームレート扱いになって `fps` フィルタで 1 フレーム補間される。そのため出力フレーム数は、非コンテナのフレーム数より 1 多い

仮説・既知の制限:
- MCSR のリサイズ (縦長の目測モード等) でハートが画面外に出ると、ゲーム画面が「その他GUI」と判定される (gapcheck の 9:42〜9:48 付近)。コンテナGUI の時間には影響しない
- GUI スケールが極端に小さい (パネルが解析範囲の 5% 未満) 録画では検出できない可能性がある
- テクスチャパックでパネル色が #C6C6C6 から外れる場合は検出できない

2026-11-02 (プレビューのシーク)

観察:
- 旧方式はフレームごとに ffmpeg を起動していた。起動だけで約 260ms、GOP 途中へのシークを含めて 1 回 0.5〜0.9 秒かかっていた。gapcheck のキーフレーム間隔は 2 秒 (120 フレーム)
- ffmpeg を常駐させて前方へ読み進め、ジャンプ時だけ直前のキーフレームから起動し直す方式に変えた。デコードしたフレームは 150 枚までキャッシュする。1 フレーム送り・戻し、30〜60 フレームの移動はいずれも 0.2 秒以内に表示され、境界フレーム (#1803 ゲーム画面、#1804 インベントリ) は旧方式と一致した
- `-hwaccel d3d11va` は 1 枚の取得に 2.3 秒かかり、ソフトウェアデコードより遅かったので採用していない
